# Tableau Data Dictionary

Every field in the handoff package. Generated by `scripts/export_tableau.py`,
which reshapes published outputs without recomputing anything.

Conventions across all files:

- `geoid` is a five-character string. Keep it as a string in Tableau, or the
  leading digits of the state code can be lost in some import paths.
- Missing values are genuinely null, written as an empty CSV cell and as JSON
  `null`. There are no `"None"`, `"n/a"` or `"not available"` strings.
- Booleans are the literals `TRUE` and `FALSE`.
- Numbers are exported at source precision with no rounding, thousands
  separators or symbols. Formatting is left to Tableau so the file stays
  identical to the published tables.
- Scores are on a 0 to 100 scale **relative to the other 132 Virginia
  jurisdictions**. A score of 80 means high within Virginia, not in absolute
  terms. This applies to every field ending in `_score`.

A limitation that applies to every field: this is a county-level screen. It
cannot see parcel availability, land cost, zoning, or drive time. Full
detail in `outputs/reports/limitations_report.md`.

## county_dashboard_data.csv

133 rows, one per Virginia county-equivalent. Grain: `geoid`.

### Identity and geography

| Field | Label | Type | Definition | Source | Transformation | Format | Limitation |
|---|---|---|---|---|---|---|---|
| `geoid` | County GEOID | String(5) | Federal county code, state 51 plus a three-digit county code | TIGER/Line 2023 | None | `51001` | Independent cities have their own codes and are separate rows |
| `county_name` | County | String | Official name including the type suffix | TIGER/Line 2023 (NAMELSAD) | None | `Henrico County`, `Richmond city` | Five name pairs differ only by suffix, for example Richmond County and Richmond city |
| `county_type` | Jurisdiction type | String | Whether the row is a county or an independent city | Derived | `is_independent_city` 1 becomes Independent city, 0 becomes County | `County` | Virginia's independent cities are county-equivalents, not inside counties |
| `latitude` | Latitude | Float | Geographic centroid | Derived from TIGER geometry | Centroid computed in EPSG:26918, reported in EPSG:4326 | Decimal degrees | A centroid can fall outside an irregular boundary and is not a store location |
| `longitude` | Longitude | Float | Geographic centroid | Derived from TIGER geometry | As above | Decimal degrees | As above |
| `land_area_sq_mi` | Land area | Float | Land area excluding water | TIGER/Line ALAND | Square metres divided by 2,589,988.11 | Square miles | Water area is excluded, so coastal jurisdictions look smaller than their mapped extent |

### Demographics and economy

| Field | Label | Type | Definition | Source | Transformation | Format | Limitation |
|---|---|---|---|---|---|---|---|
| `population` | Population | Integer | Total population | ACS 5-year 2019-2023, table B01003 | None | Whole number | A period estimate describing a 60-month window, not a point-in-time count |
| `population_change_pct` | Population change % | Float | Change between the 2014-2018 and 2019-2023 ACS periods | ACS 5-year, both periods | `(current - prior) / prior * 100` | Percent, for example `14.39` | A change between two period estimates, not an annual growth rate |
| `median_household_income` | Median household income | Float | Median household income | ACS 5-year 2019-2023, table B19013 | None | US dollars | Expressed in 2023 dollars, the final year of the period |
| `nominal_income_change_pct` | Income change, nominal % | Float | Change in median household income, not inflation adjusted | ACS 5-year, both periods | `(current - prior) / prior * 100` | Percent | Not a purchasing-power measure. Use the real field for that |
| `real_income_change_pct` | Income change, real % | Float | Change with both periods expressed in 2023 dollars | ACS 5-year plus BLS CPI-U | Prior period multiplied by 1.21343, then percent change | Percent | The deflator is national CPI-U, not a Virginia or metro-specific index |
| `population_density` | Population per sq mi | Float | Residents per square mile of land | Derived | `population / land_area_sq_mi` | People per square mile | A county average hides variation between its urban and rural parts |

### Highway and access

| Field | Label | Type | Definition | Source | Transformation | Format | Limitation |
|---|---|---|---|---|---|---|---|
| `max_interstate_segment_adt` | Max interstate segment ADT | Float | Highest single interstate mainline segment reading in the jurisdiction | VDOT Traffic Volume 2024 | Maximum ADT over mainline segments, with ramps, rest areas and weigh stations excluded by rule | Vehicles per day | **Not** countywide average traffic and **not** a two-way total. VDOT records each carriageway separately with differing values. Null for 90 jurisdictions, so always pair with `traffic_data_available_flag` |
| `distance_to_interstate_mi` | Distance to interstate | Float | Centroid to the nearest interstate centreline | TIGER primary roads | Straight-line distance in EPSG:26918, converted to miles | Miles | Straight-line, not drive time. Measured from the centroid, not from a candidate site |
| `nearest_store_distance_mi` | Nearest store, any status | Float | Centroid to the nearest open, announced, under construction or locally approved store | Compiled store list | Straight-line distance | Miles | Treats planned stores as though operating, which is deliberately conservative |
| `nearest_open_store_distance_mi` | Nearest open store | Float | Centroid to the nearest store that is trading today | Compiled store list | Straight-line distance | Miles | Only one Virginia store is open, so most values are driven by out-of-state stores |
| `interstate_access_flag` | Interstate present | Boolean | Whether an interstate physically crosses the jurisdiction | TIGER primary roads | Spatial intersection test | `TRUE` / `FALSE` | Presence of a road, not of a usable interchange |
| `traffic_data_available_flag` | Traffic data available | Boolean | Whether VDOT's extract holds a mainline record for this jurisdiction | Derived | `max_interstate_segment_adt` is not null | `TRUE` / `FALSE` | 13 jurisdictions, including Newport News and Hampton, are crossed by an interstate with no matching record, so this is `FALSE` while `interstate_access_flag` is `TRUE` |

### Commercial activity

| Field | Label | Type | Definition | Source | Transformation | Format | Limitation |
|---|---|---|---|---|---|---|---|
| `gas_stations` | Gas stations | Float | Establishments in NAICS 447, gasoline stations | County Business Patterns 2023 | None | Whole number | Counts premises, not capacity. A 120-pump travel centre and a two-pump rural station each count once. Null where CBP publishes no row |
| `gas_stations_per_10k` | Gas stations per 10k | Float | Fuel retail density | Derived | `gas_stations / population * 10,000` | Rate | Inherits the counting limitation above |
| `food_service_establishments` | Food service establishments | Float | Establishments in NAICS 722, food services and drinking places | County Business Patterns 2023 | None | Whole number | Same counting limitation. Null where CBP publishes no row |

### Screening geography

| Field | Label | Type | Definition | Source | Transformation | Format | Limitation |
|---|---|---|---|---|---|---|---|
| `corridor` | Corridor | String | Analyst-defined highway market grouping | Analyst definition, validated against VDOT records | Membership assigned by county | `I-64 / I-264 Hampton Roads` | 60 jurisdictions sit outside any screened corridor and carry `Not in a screened corridor`. | `vdot_district` | VDOT district | String | VDOT construction district | VDOT Traffic Volume 2024 | Most frequent district across the county's own segments | `Hampton Roads` | **A maintenance administration boundary, not a retail trade area.** Do not present as a market. The Staunton district runs from Winchester to Augusta County |

### Scores and ranks

| Field | Label | Type | Definition | Source | Transformation | Format | Limitation |
|---|---|---|---|---|---|---|---|
| `market_attractiveness_score` | Attractiveness score | Float | Weighted composite under the balanced scenario | Scoring model | Weighted sum of the eight component scores | 0 to 100 | Relative to Virginia. Not a recommendation on its own, see `recommendation_status` |
| `balanced_rank` | Balanced rank | Integer | Rank under the balanced scenario | Scoring model | 1 is strongest of 133 | 1 to 133 | Ties broken deterministically by GEOID |
| `highway_rank` | Highway-first rank | Integer | Rank under the highway-weighted scenario | Scoring model | As above | 1 to 133 | As above |
| `growth_rank` | Growth-chasing rank | Integer | Rank under the growth-weighted scenario | Scoring model | As above | 1 to 133 | As above |
| `affluent_rank` | Affluent-markets rank | Integer | Rank under the income-weighted scenario | Scoring model | As above | 1 to 133 | As above |
| `underserved_rank` | Underserved-markets rank | Integer | Rank under the competition-weighted scenario | Scoring model | As above | 1 to 133 | As above |
| `market_demand_score` | Market demand | Float | Population and commuter volume | ACS 5-year | Blend of log-scaled population and commuters, re-normalized | 0 to 100 | Size only. Says nothing about willingness to stop |
| `growth_score` | Growth | Float | Population and income momentum | ACS 5-year, both periods | Blend weighted 0.7 population, 0.3 income, re-normalized | 0 to 100 | Backward looking. Past change is not a forecast |
| `purchasing_power_score` | Purchasing power | Float | Household and per-capita income | ACS 5-year 2019-2023 | Blend weighted 0.6 median household, 0.4 per capita | 0 to 100 | Resident income, not the income of passing travellers |
| `highway_opportunity_score` | Highway opportunity | Float | Interstate traffic exposure | VDOT 2024 | Blend of max interstate ADT and a log-scaled volume proxy | 0 to 100 | Jurisdictions with no interstate score zero exposure rather than null |

| `low_competition_score` | Low competition | Float | **Inverted.** Higher means thinner fuel retail | CBP 2023 | Min-max of negative gas stations per 10k | 0 to 100 | Higher is more attractive. Do not read as more competition |
| `low_overlap_risk_score` | Low overlap risk | Float | **Inverted.** Higher means farther from another store | Compiled store list | Min-max of distance, capped at 120 miles | 0 to 100 | Higher is more attractive. The 120-mile cap flattens differences among remote counties |

### Recommendation

| Field | Label | Type | Definition | Source | Transformation | Format | Limitation |
|---|---|---|---|---|---|---|---|
| `recommendation_status` | Recommendation status | String | Outcome of the eligibility screen | Analyst screen | First matching rule of eight | `Priority candidate` | The decision field. Never present a rank as advice without it |
| `recommendation_reason` | Reason | String | Why that status was assigned | Analyst screen | Generated from the matching rule and its inputs | Sentence | Free text. Use in tooltips, not as a dimension |
| `overlap_review_flag` | Needs overlap review | Boolean | Whether the jurisdiction sits 30 to 40 miles from a store | Analyst screen | Distance band test | `TRUE` / `FALSE` | Flags proximity that needs trade-area work. `TRUE` does not mean rejected |
| `development_status` | Development status | String | Status of a store already in the jurisdiction | County and state sources | Null where no store exists | `open`, `announced`, `locally approved` | Populated for only 3 of 133 rows. Null means no store, not unknown |

**Status values and their meaning**

| Value | Rows | Meaning |
|---|---|---|
| `Priority candidate` | 9 | Clears every screen, top 25 balanced, and top 25 in at least 4 of 5 scenarios |
| `Secondary candidate` | 8 | Clears every screen, top 45 balanced |
| `Watchlist` | 10 | Clears every screen, outside the ranking cutoffs |
| `Reference case` | 3 | Already has an open, announced or locally approved store |
| `Overlap constrained` | 29 | Within 30 miles of an existing or planned store |
| `Feasibility constrained` | 4 | Density at or above 2,000 per square mile, so an interchange-scale site is implausible |
| `Traffic data unavailable` | 13 | An interstate crosses it but VDOT holds no mainline record, so it is held back for data reasons rather than on merit |
| `Ineligible: no interstate access` | 57 | No interstate crosses the jurisdiction |

## component_definitions.csv

8 rows, one per model component. Grain: `component`.

A plain-language reference for what each component measures. Built for
tooltips, a methodology sheet, and anyone who needs to explain the model
without reading the code. It contains no county data.

| Field | Label | Type | Definition | Source | Transformation | Format | Limitation |
|---|---|---|---|---|---|---|---|
| `component` | Component | String | The component key | Scoring model | None | `highway_opportunity` | Matches `scenario_weights.csv` and `component_scores_long.csv`, so all three join on it |
| `plain_english_definition` | Definition | String | What the component measures, without jargon | Written for this handoff | None | Sentence | Prose, not a formula. The exact formulas are in `outputs/reports/methodology_report.md` |
| `input_variables` | Input variables | String | The raw fields feeding the component, semicolon separated | `scripts/analyze/scoring.py` | Read from the model code | `total_population; commuters_total` | Names the inputs, not the weights or transforms applied to them |
| `higher_score_meaning` | What a high score means | String | How to read a high value | Scoring model | None | Sentence | Two components are inverted and say so explicitly |
| `primary_source` | Primary source | String | Where the inputs come from | Source inventory | None | `County Business Patterns 2023, NAICS 447` | Names the main source. Full provenance is in `docs/citations.md` |
| `key_limitation` | Key limitation | String | The most important caveat for that component | Limitations report | Condensed to one entry per component | Sentence | The single most material caveat, not the full list |

An automated check confirms all 13 named input variables exist as real fields
in the source tables, so this file cannot drift into describing inputs the
model does not use. A second check confirms `competition` and `overlap_risk`
are the only two rows stating the inverted direction.

Use this file to drive tooltips on component views. Joining it to
`component_scores_long.csv` on `component` puts the definition and the
limitation next to the number a viewer is looking at, which is where a caveat
actually gets read.

## component_scores_long.csv

1,064 rows: 133 counties multiplied by 8 components. Grain:
`geoid` + `component`.

The same eight component scores as the wide county file, reshaped so each
score is its own row. Use this for component comparison views, small
multiples and heatmaps, and for joining to `scenario_weights.csv` to show
how each component contributes to a county's total.

| Field | Label | Type | Definition | Source | Transformation | Format | Limitation |
|---|---|---|---|---|---|---|---|
| `geoid` | County GEOID | String(5) | Federal county code | TIGER/Line 2023 | None | `51001` | Repeats eight times, once per component. Not unique on its own |
| `county_name` | County | String | Official name | TIGER/Line 2023 | Repeated across the county's eight rows | `Henrico County` | Denormalized for convenience |
| `component` | Component | String | Which of the eight components the score belongs to | Scoring model | Unpivoted from the wide column names | `highway_opportunity` | Uses the `scenario_weights.csv` key, not the wide file's column name. See the note below |
| `component_score` | Score | Float | The component score | Scoring model | Unpivoted, unchanged | 0 to 100 | Relative to Virginia. Two components are inverted, see below |
| `recommendation_status` | Recommendation status | String | Outcome of the eligibility screen | Analyst screen | Repeated across the county's eight rows | `Priority candidate` | Denormalized. Filtering on it filters whole counties, not individual components |
| `corridor` | Corridor | String | Highway market grouping | Analyst definition | Repeated across the county's eight rows | `I-95 Richmond South` | Denormalized. 60 counties carry `Not in a screened corridor` |

**Why `component` uses a different name from the wide file.** The wide file
calls two of these `low_competition_score` and `low_overlap_risk_score`, so a
reader cannot mistake their direction. This file instead uses the keys
`competition` and `overlap_risk`, matching `scenario_weights.csv`, because
the main reason to have a long format is to join it to the weights. A key
that did not join would defeat that. Joining brings `component_label` across,
which carries the direction wording (`Low Competition`, `Low Overlap Risk`),
so use the label on any axis a viewer will read.

| `component` value | Direction | Label after joining to weights |
|---|---|---|
| `market_demand` | Higher is more attractive | Market Demand |
| `growth` | Higher is more attractive | Growth |
| `purchasing_power` | Higher is more attractive | Purchasing Power |
| `highway_opportunity` | Higher is more attractive | Highway Opportunity |
| `accessibility` | Higher is more attractive | Accessibility |
| `commercial_activity` | Higher is more attractive | Commercial Activity |
| `competition` | **Inverted.** Higher means thinner existing fuel retail | Low Competition |
| `overlap_risk` | **Inverted.** Higher means farther from another store | Low Overlap Risk |

Every value is identical to the corresponding cell in
`county_dashboard_data.csv`, and there are no nulls: all 133 counties have all
eight scores.

## virginia_counties.geojson

133 features. CRS is WGS84, declared as `urn:ogc:def:crs:OGC:1.3:CRS84`, which
is the GeoJSON default.

Each feature carries the **same 41 properties as the county CSV**, with
identical values and the same null handling, plus a `geometry` member of type
`Polygon` or `MultiPolygon`. Field definitions above apply unchanged.

MultiPolygon appears where a jurisdiction includes islands or detached parts,
which is common on the Eastern Shore and in Hampton Roads. Tableau renders
both types without configuration.

Because this file already carries every county attribute, it can drive an
entire workbook on its own. See `tableau_build_notes.md` for when to use it
rather than the CSV.
